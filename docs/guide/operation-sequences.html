Domain ID 갱신 — 파일은 전파되고, 컨테이너는 재생성돼야 한다

도메인은 프로세스 시작 시점에만 읽힌다. 파일만 바꾸면 실행 중 컨테이너는 옛 도메인에 머문다.

순서가 정보다
adsw_manager 는 Autoware 를 띄울 때 ${ROS_DOMAIN_ID} 를 자기 셸 env 로 확장한다. ext-ros2 를 먼저 재생성하지 않으면 몇 번 재시작해도 옛 도메인.
왜 호스트인가
재생성 대상 안에 실행 주체가 있다 — adsw_manager 는 ext-ros2 안, agl_adsw_manager 는 ext-agl 안. lfc_monitor 로는 자기를 죽이게 된다.
셸 오염
compose 는 셸 env 가 --env-file 을 이긴다. 151 의 ~/.bashrc 에 ROS_DOMAIN_ID=1 이 있어 반쪽 적용이 났다 — 도메인 파일을 마지막에 source.

02

컨테이너 · 서비스 시작 / 종료 — ctrl 평면과 액추에이터

lfc_monitor 의 버튼 하나가 브릿지 → lifecycle_mgr 게이트 → adsw_manager → docker 를 지난다. 응답은 같은 길로 되돌아온다.

Stop = 삭제
정지만 원해도 컨테이너가 제거된다. 그래서 Start 는 항상 목록의 인자로 재생성이고, 그 덕에 도메인 같은 env 가 새로 반영된다.
이름이 없는 응답
CtrlResponse 는 ret_code 한 필드뿐 — 대상 이름이 없다. lfc_monitor 가 자기 요청과 짝지어 표시하고, 짝이 없으면 (unsolicited).
observe_only
플랫폼 컨테이너(core · ext-ros2 · ext-agl)는 게이트에서 거부된다 — 호스트 compose 가 소유하고, 실행 주체가 그 안에 있기 때문.

rviz2 시작 / 종료 — 패널이 docker 를 직접 다룬다

F010 direct-docker: rviz2 는 adsw 관리 대상이 아니다. 런처 안의 rviz2_panel 이 docker.sock 과 AGL 셸 gRPC 로 직접 제어한다.

도메인이 어긋나면 빈 화면
맵 토픽은 TRANSIENT_LOCAL 이라 늦게 붙어도 받는다. 그래서 화면이 비었다면 대개 도메인 불일치다 — 발행자 0, 구독자 1 로 확인된다.
Run Options 는 저장된다
Start 시 config.json 에 기록되어 앱 재시작 후에도 유지되고, 그 뒤로는 런처 Settings 가 이 값을 덮지 않는다. 되돌리려면 “기기 기본값으로”.

04

이미지 배포 — :latest 는 흐르고 :provision 은 기준선이다

develop 커밋이 보드에 닿는 길은 둘이다: 레지스트리 pull(수시)과 Yocto 이미지에 구워진 아카이브(플래싱).

preload 는 덮지 않는다
:latest 가 이미 있으면 태깅을 생략한다 — oss-provision 이 pull 한 최신본을 보존하기 위해서다.
아치를 명시할 것
:latest·:provision 은 멀티아치 매니페스트다. 보드용은 --platform linux/arm64 로 뽑아야 한다.
베이크본이 낡아도
수정은 프로비저닝 시점에 도착한다. 다만 네트워크 없는 첫 부팅은 베이크본이 전부다 — 그래서 베이크 갱신이 필요했다.

05

상태 관측 — docker inspect 가 lfc_monitor 카드가 되는 길

누가 만든 컨테이너인지 묻지 않는다. 등록만 되어 있으면 관측되고, 그래서 관찰 전용 노출이 가능하다.

지연의 두 층
최악 3초(폴) + 전이 시 즉시 발행. 카드가 늦게 바뀌면 대개 폴 주기 안이다 — 버그가 아니다.
하트비트가 필요한 이유
브릿지가 VOLATILE 이라 latch 가 없다. 무변화 재발행이 없으면 나중에 접속한 lfc_monitor 는 빈 화면을 본다.
낙관적 갱신
버튼을 누르면 UI 가 먼저 상태를 칠한다. 다음 DiagReport 가 서버 측 진실로 덮어쓴다.

06

dds_bridge — 두 평면을 잇고, 유령 발행자를 걸러낸다

raw IDL 타입과 ROS 정규 타입은 XTypes 해시가 달라 그냥은 매칭되지 않는다. 브릿지가 같은 TypeObject 를 두 이름으로 등록해 잇는다.

pin 은 영구가 아니다
unmatch 에 해제된다. 이게 없으면 발행자를 재기동했을 때 영원히 드롭되고 브릿지 재시작만이 복구였다.
trust-on-first-use 의 대가
유령이 먼저 발행하면 유령을 신뢰한다. 정상 발행자(core·adsw)가 ROS 구독자보다 먼저 뜨기에 감수한 트레이드오프다.

07

공장 초기화 · 재프로비저닝 — 순서가 경합을 없앤다

초기화는 컨테이너를 먼저 지우고 파일을 나중에 쓴다. 그래서 도메인 파일 감시가 끼어들 자리가 없다.

가드가 필요 없는 이유
제거(①)가 파일 쓰기(④)보다 먼저다. 감시가 발화해도 볼 컨테이너가 없다. 일반 프로비저닝은 domain.env 를 아예 쓰지 않는다.
부팅 시엔 발화하지 않는다
PathChanged 는 inotify 기반이다 — 파일이 이미 있는 상태로 감시를 시작해도 조용하다(PathExists 와 다른 점).
백업도 지운다
초기화는 agl-service-list.yaml.bak-* 를 정리한다. 남겨야 할 사본은 다른 경로에 두어야 한다.
