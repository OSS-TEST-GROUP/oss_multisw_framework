SiLS · MORAI · Autoware · 데이터 흐름 정리

제어 계층과 DDS 버스

제어는 위→아래로 내려간다: Autoware(목표) → Vehicle Interface(아비트·안전·변환) → brake · steer · powertrain ECU(액추에이터별 구동) → MORAI(동역학). 모든 링크는 DDS 버스 토픽 — 데이터가 누굴 "거치지" 않고 각자 필요한 것만 구독한다. 폐루프는 MORAI에서 닫힌다.

STATE / SENSOR — MORAI 생산 명령 (CONTROL target · setpoint) ACTUATION — ECU → MORAI

① 전체 토폴로지 — MORAI (폐루프)

MORAI가 DDS 토픽(VSS 신호)으로 STATE를 실시간 broadcast → 소비자들이 각자 구독. 제어는 Autoware→VI→ECU로 내려가고, ACTUATION이 MORAI로 되돌아가 새 STATE를 만든다(폐루프 ↺).

계층 ①

Vehicle Interface = 조정자

Autoware의 차량-무관 목표(가속·조향)를 받아 아비트레이션·안전제한·변환 후 액추에이터별 setpoint로 분배. Autoware의 vehicle_interface.

계층 ②

brake / steer / powertrain = 손발

각자 자기 setpoint + 관심 STATE만 구독해 단일 액추에이터를 구동, ACTUATION을 MORAI로. 도메인이 좁고 명확한 vECU.

계층 ③

폐루프는 MORAI에서

ACTUATION → MORAI 동역학 → 새 STATE → (모두 다시 구독). Autoware/VI 로 되돌아가지 않고 다음 STATE로 결과가 관측된다.

② 전체 토폴로지 — rosbag (개루프 재생)

rosbag은 MORAI와 동일한 DDS 토픽/타입으로 녹화된 STATE를 재생한다. 그래서 소비자(Autoware·VI·ECU)와 제어 체인은 ① 그림과 완전히 동일하게 동작한다. 유일한 차이는 ACTUATION이 rosbag으로 돌아가지 않는다(로그/폐기) — 폐루프가 열린다(개루프).

③ 요약 비교 — MORAI vs rosbag

소비자(Autoware·VI·ECU)는 양쪽에서 똑같이 동작한다. 차이는 딱 하나 — 제어(ACTUATION)가 세계로 되돌아가느냐. MORAI는 반응해 루프가 닫히고, rosbag은 무시해 루프가 열린다.

④ Web.Auto 활용 — 관리 플레인은 폐루프 "위"에 얹힌다

실제 시뮬레이션 폐루프(MORAI/AWSIM ⇄ DDS ⇄ vECU·Autoware)는 로컬/엣지에서 실시간으로 돈다 — 고대역 센서 버스라 클라우드로 올리지 않는다. Web.Auto는 이 루프 안이 아니라 위에 얹히는 클라우드 관리 플레인으로, 매 tick 센서값이 아니라 런의 "결과·기록"(rosbag·평가 메트릭·텔레메트리)을 다룬다. MORAI의 대체재가 아니라 다른 계층이다 (MORAI 등가물은 TIER IV의 AWSIM).

활용 A — 클라우드 자기완결

Autoware 스택 회귀 (logsim)

Web.Auto가 클라우드 안에서 rosbag → Autoware 인스턴스 → 평가까지 다 돌린다. 로컬 vECU는 관여하지 않음. Autoware 스택 자체의 회귀·시나리오 검증에 적합.

활용 B — 데이터 소스

vECU 회귀 (로컬 replay+verify)

Web.Auto는 rosbag 공급자 역할만. 내려받은 rosbag을 로컬 SiLS 개루프(② 그림)로 재생 → trace 기반 결정론 판정. vECU 로직 회귀는 이쪽. verify 주체·위치가 로컬이다.
