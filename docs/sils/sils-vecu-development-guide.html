01

큰 그림 — SiLS 런 생태계

한 번의 SiLS 런은 여러 프로세스가 같은 DDS 도메인에 모여 돈다. 내가 만드는 건 vECU 하나뿐 — 나머지는 SDK 가 함께 제공하는 fixture/도구이고, 컨테이너 기동은 MMF 오케스트레이션이 맡는다.

vECU (probe)

내가 개발. 매 틱 emit. behavior/plant/wire → RunProbe. 컨테이너 1개 = 인스턴스 1개.

responder

SUT 대역(§L1). 요청 토픽 구독→상관 응답 발행. 실물 viss-server 로 대체 가능.

verifier

독립 구독자. 샘플 수신·trace 적합성 증명. gate.py 로 판정.

clock_master

lockstep 시간 마스터. TickGrant 발행→모든 참가자 TickComplete 대기(§8.2).

input_source

async 입력 fixture. TickInbox 스테이징(§7.3) 관측용. 프로덕션 아님.

lifecycle_mgr + adsw

경로 B 오케스트레이션. 등록→정책 자동기동→docker run. ROS2 불필요.

결합 모드 2가지. 위는 VISS 요청 모델(요청/응답, RunProbe). 시뮬레이터(MORAI/AWSIM)와 폐루프로 붙는 vECU 는 플랜트 결합 모드(§07)를 쓴다 — 버스에서 STATE 구독·ACTUATION 발행. §02~§06 은 VISS 모델 기준.
02

vECU 내부 — 포트 5개 + RunProbe

vECU 는 ConfigFromEnv 로 env 를 읽고, 포트를 조립해 RunProbe 에 넘기는 ~25줄 실행파일이다. 굵은 3개가 주입(개발자 작성), 나머지 2개는 RunProbe 가 config 로 내부 생성.

03

틱 루프 — RunProbe 가 도는 방식

매 틱마다 clock 이 시간을 주고, behavior 가 출력을 계산하고, wire 가 DDS 에 싣고, plant 가 물리를 한 스텝 전진시켜 다음 틱 behavior 로 피드백된다(폐루프 §9 L3).

04

개발 절차 (요약)

전체 코드/CMake 스니펫은 .md 가이드에. 여기선 흐름만.

  1. 뼈대

    examples/brake-ecu/ 복사. in-tree 는 examples/CMakeLists.txt 에 등록, out-of-tree 는 find_package(sils_vecu).

  2. IBehavior 구현 (필수)

    OnTick(ctx) 가 {request_json, value} 반환. 결정적이어야 golden 재현.

  3. IPlant (선택)

    폐루프면 code 구현 / MakeFmuPlant / open-loop 는 nullptr.

  4. IWireCodec 선택

    내장 VISS 재사용(계약 무변경) 또는 커스텀 타입(상대편도 그 타입 알아야 함).

  5. main.cc

    ConfigFromEnv → 포트 조립 → RunProbe(cfg, behavior, plant, wire).

  6. CMake · descriptor · 패키징

    target_link_libraries(... sils_vecu); env 계약 descriptor; entrypoint 는 바이너리를 PID 1 로 exec.

06

경로 B — 실 lifecycle_mgr 로 배포

이미지를 speclist 에 등록하고 두 프로세스를 같은 도메인에 띄우면, recovery: ALWAYS 일 때 트리거 없이 자동 기동된다. (검증된 흐름)

실행: ./build.sh --build-sils → ./docker/build_local.sh --sils-vecu-only(또는 --brake-ecu-only) → e2e/run_lifecycle_e2e.sh. 같은 MMF_DDS_DOMAIN_ID 로 lifecycle_mgr 와 adsw 를 띄운다.
07

플랜트 결합 모드 — MORAI/AWSIM (Option 2)

시뮬레이터(MORAI/AWSIM)와 폐루프로 붙는 vECU 는 VISS 요청 모델과 달리 버스 위 공유 세계(authority=sim)에서 STATE 를 구독하고 ACTUATION 을 발행한다. plant 가 in-process IPlant 가 아니라 DDS 버스 너머에 있고, 폐루프는 시뮬레이터가 버스에서 닫는다. 설계: plant-adapter-design.

VISS 요청 (§02~§06)플랜트 결합 (이 절)
진입점RunProbe (run_loop.hpp)sils_vecu_vehicle_probe
방향요청 발행 → 응답STATE in → CONTROL out
DDS 타입VissRequestTopicEgoState / VehicleControl (구조체)
코덱IWireCodec (viss_wire)VehicleWireCodec (vehicle_wire)
토픽 선언단일 토픽 (SILS_TOPIC)채널맵 (SILS_CHANNELMAP, N채널 MIMO)
정규 계약

EgoState.idl(STATE in)·VehicleControl.idl(ACTUATION out). SI 단위. 시뮬이 자기 메시지를 이 타입으로 번역(anti-corruption).

채널맵

config/sils/channelmap/*.yaml — name(VSS)·dir·topic·type. 채널 추가로 MIMO 확장(예: Autoware 제어 입력).

코덱 + fixture

vehicle_wire.hpp(구조체↔POD). sils_ego_source 로 MORAI 없이 왕복 실증.

로컬 왕복 확인 (MORAI 없이):

export VISS_DDS_DOMAIN_ID=0 SILS_RUN_ID=rt
# A — vECU 프로브 (먼저 띄워 구독 준비)
SILS_CHANNELMAP=config/sils/channelmap/ego-min.yaml  bin/sils_vecu_vehicle_probe
# B — EgoState 소스 (fixture)
bin/sils_ego_source --count 20 --rate-ms 100
# → 프로브에 state_received(vx↑) → control_published(제어 반응) 가 흐르면 왕복 성립
성숙도 (2026-08): S1~S5 전부 완료·머지 — S1 free-run(채널맵·정규계약·코덱·프로브·fixture), S2 tick 경계 staging(SILS_STAGE_INPUT=1), S3 lockstep(SILS_CLOCK_MODE=lockstep), S4 conformance(버스 결합 이벤트가 trace schema v1 에 등록, analyze_vehicle 판정), S5 결함 주입(SILS_INPUT_FAULTS + analyze_fault). 전용 behavior 포트 IVehicleBehavior 도 도입됨(vehicle_behavior.hpp, 기본 구현 LongitudinalBehavior). 남은 것 — Autoware 제어 입력(control_cmd→ControlTarget)과 실 브리지 #1(BR-C-1 clock 답 확인 후). MORAI→DDS 어댑터는 외부(SiLS 밖).
