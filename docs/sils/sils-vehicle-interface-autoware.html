SiLS · Vehicle Interface(VCU) · Autoware 연동 — 검토 단계

Autoware → VCU → MORAI

MORAI는 단일 통합 명령(CtrlCmd)만 받는다. Autoware의 제어를 MORAI에 넣으려면 그 사이에서 받아 아비트·안전·통합·변환하는 Vehicle Interface(VCU)가 필요하다 — 개별 액추에이터 ECU가 MORAI로 직행하는 게 아니다. Autoware 실소스(/Volumes/DATAPart/AUTOWARE) 기준.

Autoware 제어 (Control · Gear) VCU → plant (통합 VehicleControl) STATE / report (EgoState · status)

① 토폴로지 — 전체 AD 폐루프

② Autoware 제어 인터페이스 (실측)

autoware_vehicle_cmd_gate가 아비트 후 최종 명령을 낸다. VCU는 실차 vehicle_interface 노드와 같은 자리에서 이 경계를 소비/생산한다.

방향토픽타입 · 핵심 필드(단위)
구독/control/command/control_cmdControl — lateral.steering_tire_angle(rad), longitudinal.velocity(m/s)·acceleration(m/s²)·jerk
구독/control/command/gear_cmdGearCommand — command(NEUTRAL=1, DRIVE=2, REVERSE=20, PARK=22)
발행/vehicle/status/steering_statusSteeringReport — steering_tire_angle(rad)
발행/vehicle/status/velocity_statusVelocityReport — longitudinal/lateral_velocity, heading_rate(rad/s)
발행/vehicle/status/gear_statusGearReport

단위가 우리 정규 계약과 거의 일치 — steering_tire_angle=rad(=우리 steering_angle), longitudinal.acceleration=m/s²(=우리 것). MORAI(deg·km/h)보다 변환 부담이 훨씬 작다(gear enum 매핑 정도).

③ 결정 — 정규 미러 (Option i)

ControlTarget.idl(정규 미러)를 두고, Autoware↔DDS 브리지(외부)가 autoware_control_msgs/Control→ControlTarget 번역. VCU는 정규만 소비 → MORAI를 EgoState 정규로 받은 것과 대칭.

Autoware는 ROS2(=DDS)라 제어 타입이 이미 DDS지만, FastDDS vECU가 직접 구독하려면 ROS2 type name/hash·CDR·QoS·ROS_DOMAIN_ID·rmw 호환을 모두 맞춰야 한다(integration-review §3.4). 그 난관을 브리지(외부 anti-corruption layer)로 밀어낸다 — 브리지는 SiLS 소유 아님(MORAI 어댑터와 동일).

④ 정규 계약 + 매핑 체인

struct ControlTarget {   // idl/dds/sils/ControlTarget.idl (Autoware 제어 미러)
    string run_id; unsigned long long seq; long long stamp_ns;
    double steering_angle;   // rad   (= Control.lateral.steering_tire_angle)
    double acceleration;     // m/s²  (= Control.longitudinal.acceleration, 단일 모드)
    octet  gear;             // 0=P 1=R 2=N 3=D
};
단계변환주체
Autoware Control → ControlTargetsteering_tire_angle→steering_angle, longitudinal.acceleration→acceleration브리지(외부)
GearCommand → gearDRIVE(2)→3, REVERSE(20)→1, PARK(22)→0, NEUTRAL(1)→2브리지(외부)
ControlTarget + EgoState → VehicleControl아비트·안전 클램프·통합VCU
VehicleControl → CtrlCmdrad·m/s² 유지, longl_cmd_type=accelerationMORAI 어댑터(외부)
EgoState → Steering/VelocityReportsteering→steering_tire_angle, velocity→longitudinal_velocity, yaw_rate→heading_rateVCU

ControlTarget와 VehicleControl은 필드가 사실상 동일하나 의미가 다르다 — 전자는 Autoware가 원하는 목표, 후자는 VCU가 아비트·안전 후 plant에 내리는 명령. 평시 근사 pass-through, 이상시 VCU 개입.

⑤ VCU 책임 — 아비트·안전 (궤적 제어 아님)

  1. 매핑/통합 — ControlTarget → 단일 VehicleControl.
  2. 안전 — control command 타임아웃 시 safe stop(최근 target이 N ms 이상 없으면 감속/제동).
  3. 클램프 — 조향각·가속 물리 한계·rate 제한.
  4. 리포트 — EgoState → Steering/VelocityReport 되돌림(Autoware 폐루프).
  5. 모드 — engage/emergency 반영(후속).

VCU의 "control logic"은 아비트레이션·안전 계층이지 경로 추종이 아니다(그건 Autoware). steer-ecu의 P 컨트롤러와 성격이 다르다.

⑥ 단계화 (VCU)

S0 설계

이 문서 + ControlTarget 스키마.

S1 매핑

ControlTarget+EgoState in → VehicleControl out (pass-through, free-run).

S2 리포트

Steering/VelocityReport 되돌림 + gear 매핑.

S3 안전

타임아웃→safe stop·클램프·아비트.

S4 정합

lockstep + conformance(왕복·타임아웃 판정).

외부(SiLS 밖): Autoware↔DDS 브리지, MORAI 어댑터. 프로파일 B: VehicleBehaviorContext에 target+have_target 가산 확장(기존 상태-only behavior 무변경).

⑦ 구현 계획 (합의 순서)
