MORAI / AWSIM Plant 어댑터 — 3안 비교

MORAI(또는 TIER IV AWSIM)를 SiLS vECU의 plant로 붙일 때 어느 포트로 어떻게 결합할지를 정한다. 코드보다 프레이밍 결정이 먼저 — 이 결정이 구현 전체를 가른다. 갭은 두 축이다: SISO↔MIMO, 그리고 in-process↔out-of-process(버스 너머 공유 세계).

STATE / 권장 명령 · setpoint / 절충 ACTUATION 모순 / 비권장

① 갭 — 두 축으로 정확히

현재 SDK의 plant 결합(IPlant·BehaviorContext·BehaviorOutput)은 스칼라(SISO) + in-process를 전제한다. MORAI/AWSIM은 두 축 모두 다르다.

축현재 계약MORAI / AWSIM
채널 수SISO — SetInputs(double), Step(dt)→double; plant_feedback·value 각 1개MIMO — 입력 조향·가감속·브레이크·기어…, 출력 pose·velocity·wheel_speed·gps·imu·cam·lidar…
결합 위치in-process — tick 루프가 plant->Step(dt)로 직접 적분(동기)out-of-process — 별도 시뮬레이터, DDS 버스 너머
소유권그 vECU 전용 (1:1)공유 세계 · authority=morai — N개 vECU + Autoware 동시 소비
시간 전진tick 루프가 dt 부여MORAI 물리엔진이 전진 (외부 클럭)

변경 영향 3곳: plant.hpp(IPlant), behavior.hpp(context/output 스칼라), run_loop.hpp(폐루프 닫는 지점 + plant_step trace). conformance evaluate.py analyze_plant가 feedback_in[N]==output[N-1]·상수 dt·유한값을 판정 — 세 곳 모두 스칼라를 가정한다.

② 세 가지 안

비권장

Option 1 — IPlant를 MIMO in-process 코시뮬로 확장

· 구현 규모: 중~대

IPlant 벡터화 + MoraiPlant:IPlant가 매 tick DDS로 MORAI를 한 스텝 구동. 폐루프는 여전히 tick 루프의 Step()에서 닫힌다.

장점
  • "plant는 IPlant 뒤" 멘탈모델·analyze_plant 그대로 재사용
  • Analytic/FMU와 대칭 — MakePlant("morai",…) 한 줄 스위치
  • 폐루프 연속성 판정(feedback_in[N]==output[N-1]) 그대로 성립
단점
  • 공유 세계를 한 vECU가 구동 → N-consumer 토폴로지(①/④)와 모순
  • MIMO를 behavior context/output에 강제 → 스칼라 전제 붕괴
  • lockstep을 IPlant 안에 숨김 → 실패/타임아웃이 §14 fail-fast를 흐림
권장

Option 2 — MORAI는 IPlant가 아니라 "버스 결합 외부 세계" 모드

· 구현 규모: 대(범위 넓음, 파괴적 변경 최소)

MORAI 모드에선 vECU가 로컬 plant를 안 돌린다. MORAI가 STATE를 버스에 pub → vECU는 staged 입력(기존 wire read)으로 소비, ACTUATION을 pub. 폐루프는 버스에서 닫힌다(토폴로지 ① 그대로). in-process IPlant(Analytic/FMU)는 standalone L3용으로 유지.

장점
  • 실제 토폴로지(공유 세계, N consumer)와 정합 — 두 번째 vECU도 구독만
  • MORAI 어댑터 + 다중 엔드포인트 두 티어2가 MIMO-over-DDS로 합쳐짐
  • in-process IPlant·analyze_plant 무손상 → 기존 L3 회귀 유지
  • fail-fast가 포트 뒤에 숨지 않고 wire/clock 경계에 노출
단점
  • 폐루프 연속성 판정이 더 이상 성립 안 함 → 새 conformance 관점(왕복 지연·lockstep 정합) 필요
  • BehaviorContext/Output에 다중 채널 접근자 필요(MIMO 공통 수요)
  • 채널맵/VSS 매핑이라는 새 설정 표면
절충

Option 3 — 하이브리드: IExternalPlant 얇은 포트로 Option 2를 "plant 모드"로 노출

· 구현 규모: 중

Option 2의 채널맵+lockstep을 새 포트 IExternalPlant 뒤에 두고 개념적으로 여전히 "plant"로 부른다. MakePlant("morai",…)가 in-process 대신 external 반환; RunProbe는 external이면 Step()을 호출하지 않고 "버스가 닫는다"를 안다.

장점
  • 개발자 API에서 "plant를 고른다"는 일관성 유지
  • Option 2의 토폴로지 정합 + Option 1의 "plant 뒤" 멘탈모델 절충
단점
  • 포트 하나 더(IPlant+IExternalPlant) — 실소비자 1개뿐이면 earned-abstraction 위반 소지
  • in-process vs external 분기가 RunProbe에 노출 → "숨긴다" 이점 반감

③ 부차 결정 — 시간 동기 (모든 안 공통)

방식내용SiLS 적합성
lockstepMORAI가 vECU tick당 dt 한 번 전진. 기존 LockstepClock/TickComplete 확장결정론 보장 → 목표. MORAI/AWSIM이 외부 스텝 제어를 지원해야 함
free-runMORAI 실시간 자유주행, vECU는 최신 샘플 채택비결정론(재현성↓). S1 초기 브링업/데모용

AWSIM은 ROS2 네이티브라 lockstep 제어 훅(/simulation/*) 접근 용이. MORAI는 스텝 제어 API 지원 여부 확인 필요(integration-review 후속).

④ 권장안과 근거

권장: Option 2 (버스 결합 외부 세계). API 일관성이 중요하다고 판단되면 Option 3로 얇게 감싼다.
  1. 토폴로지 정합 — 확정한 ①/④ 그림이 이미 MORAI를 "버스 위 공유 세계, authority=morai"로 규정. Option 1은 정면 모순.
  2. 티어2 통합 — MORAI 어댑터 = 다중 엔드포인트 = MIMO-over-DDS. 한 번에 해결하면 중복 설계 없음.
  3. 회귀 무손상 — in-process IPlant/analyze_plant를 안 건드림.
  4. earned-abstraction — MIMO의 실소비자(MORAI)가 실제 등장 → 지금 채널맵 확정이 정당. 새 포트(Option 3)는 실수요 더 쌓이기 전 보류 가능.

⑤ 단계화 (권장안 기준)

S0 · 설계확정 ✅

이 문서 리뷰 + 프레이밍 결정. 채널맵 스키마 초안.

S1 · free-run ✅

1~2채널로 STATE 1종 구독→behavior→ACTUATION 1종 pub. 버스 왕복 실증. 정규 IDL+VehicleWireCodec+RunVehicleProbe+fixture, develop 머지.

S2 · MIMO staged ✅

in-채널마다 VehicleTickInbox<T>(§7.3 타입 버전) → tick 경계 FreezeTick. SILS_STAGE_INPUT=1 opt-in(off=S1 폴링 보존). 채널별 tick_input_frozen 불변식. behavior엔 최신-frozen(ZOH).

S3 · lockstep ✅

소스 fixture가 동일 LockstepClockSource로 barrier participant화(빌드 변경 0) — grant마다 state를 sim_time 함수로 발행+TickComplete. 값 수준 재현 회복. 실 MORAI/AWSIM 어댑터가 구현할 계약과 동형. 결정론적 1-tick lag.

S4 · conformance ✅

vehicle 이벤트 v1 스키마 등재 + analyze_vehicle(폐루프·well-formed 명령) + analyze_staging MIMO 채널 그룹화. golden 샘플이 gate.py SCHEMA+FIDELITY PASS(L3). 141 테스트 green.

S2: staging은 소비 순서 고정(local-staged), 도착 시점은 wall clock. S3: lockstep-aware 소스로 소비 값이 sim_time 함수가 되어 값 수준 재현성 회복 — 두 실행이 동일 trace. 단일 barrier라 sim↔vECU는 결정론적 1-tick I/O 지연(zero-lag은 phased barrier=향후).

⑥ 열린 질문 — 리뷰에서 결정

  1. 프레이밍: Option 2 단독 vs Option 3(포트 래핑)?
  2. 채널맵 위치: 새 yaml(config/sils/channelmap/*.yaml) vs 기존 speclist/env 확장?
  3. VSS 정합: 채널 신호명을 VISS/VSS path에 직접 바인딩(vehicle_info_mgr 계약 재사용) vs 독립 이름공간?
  4. lockstep 대상: AWSIM 우선(ROS2 훅 용이) vs MORAI 우선(원 요구)?
  5. BehaviorOutput MIMO: 스칼라 value 유지 + 채널 사이드채널 vs 구조 교체?
