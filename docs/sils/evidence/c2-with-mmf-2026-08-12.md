목표 문장이 한 런에서 성립했다 —
*"SS_v2 로 **Autoware 연동**하고 **MMF vehicle info 연동**하고 **SiLS vECU 연동**하여
**차량이 움직이는 것**"*.

그전까지는 조각이 갈려 있었다: C2(08-12 오전)는 차가 움직였지만 **MMF 가 없었고**,
C1+MMF 는 MMF 가 붙었지만 **차를 움직인 건 시나리오 각본**이었다.

## 1. 배선 — 컨테이너 8개

```

    EgoEntity ◀── concealer ◀── control_cmd ◀───────────────┐
       │             │                                      │

       │                                                     │        │

                                    │                        │        │
                              vECU 5기 ◀── autoware/control_target ◀②─┘
                                                                      │
```

([`sils-configuration-map.md`](../sils-configuration-map.md) §3 매트릭스).

## 3. ★★ 재현 조건 — 런마다 파티션 3종을 재기동해야 한다

이게 이 문서에서 제일 실용적인 부분이다. **8번 돌려 3번 성공했고, 성공 조건이 하나였다.**

| 런 | 파티션 상태 | 결과 |
|---|---|---|
| 15:07 | control 갓 재기동 | ✅ 곡선 · `errors=0` |
| 15:10 | 그대로 | ❌ `WAITING_FOR_ENGAGE` 타임아웃 |
| 15:22 | 그대로 | ❌ 〃 |
| 15:35 | control 재기동 | ✅ mode 2 · `errors=0` (측정이 창을 놓쳐 속도는 못 봄 — §4) |
| 15:43 | control 재기동만 | ❌ |
| 15:48 | control 재기동만 | ❌ |
| **15:51** | **3종 전부 재기동** | ✅ **곡선** |

### 원인 둘

**(1) Autoware 상태가 런 사이에 안 씻긴다.**
앞 런이 끝나면 `/autoware/state` 가 **3** 에 머물고, 다음 concealer 는
`WAITING_FOR_ENGAGE` 로의 전이를 기다리다 죽는다:

```
AutowareError: Simulator waited for the Autoware state to transition to
               WAITING_FOR_ENGAGE, but time is up.
```

**control 만 재기동해선 부족하다** — decision/perception 도 상태를 든다. 15:43·15:48 이
그 반증이고, 3종 전부 재기동한 15:51 에야 재현됐다.

**(2) shim·deprecated_api 가 매 실행마다 쌓인다.**
`run_localization_shim.sh` 와 `deprecated_api.launch.xml` 을 실행마다 새로 띄우면
한 벌씩 누적된다 — 3번 돌리자 **shim 2개 · deprecated_api 5개**. 같은 서비스에 서버가
여럿이면 누가 응답할지 발행 순서가 정하고, **아무도 오류를 안 낸다.**
파티션 재기동이 이것도 같이 치운다(`docker exec` 프로세스는 컨테이너와 함께 사라진다).

> `pkill` 로 지우려 했으나 컨테이너 안 uid 가 달라 `Permission denied` 로 실패했다.
> 재기동이 확실하다.

**그래서 `run_c2_with_mmf.sh` 는 매 실행 첫 단계로 파티션 3종을 재기동한다.**

## 4. 측정이 만든 거짓 신호 셋

**rig 는 멀쩡한데 측정이 거짓말했다.** 이 rig 에서 빈 결과를 받으면 **먼저 측정 도구를
의심할 것** — 브리지 카운터(`received=/published=`)는 이 셋과 무관하게 도니 그걸로 가른다.

| # | 증상 | 진짜 원인 |
|---|---|---|
| 1 | mode 2 · `errors=0` 인데 **속도 샘플이 전부 빈값** | `mode()` 대기 루프가 `timeout 6` + `sleep 2` × 10회 = **80초**를 먹었다. 주행 구간은 ~25초라 창을 통째로 놓쳤다 → **시나리오 기동 직후부터 바로 샘플링** |
| 2 | `Publisher count: 0` | 시나리오가 끝난 뒤에 쟀다. concealer 가 같이 사라진다 → **주행 중에 잰다** |
| 3 | `ros2` 조회가 전부 빈 출력 | ros2cli 데몬 사망(`Fault: RuntimeError:!rclpy.ok()`). stderr 라 `2>/dev/null` 에 먹힌다 → **`--no-daemon`** |

> ★ 셋 다 증상이 "아무 데이터도 없음" 이라 **rig 고장과 구분이 안 된다.**

## 6. 이 시험이 증명하지 않는 것

- **vECU 가 차를 몬 것이 아니다.** Autoware → concealer → 차량모델 직결이고 vECU 는
  병렬 관측자다. SS_v2 에서는 좌석을 쥔 채 명령을 넣을 수 없다(`isEgo` 분기).
  **MORAI 가 오면 그때 합쳐진다.**
- **충실도 주장이 아니다.** SS_v2 의 축약 차량모델이고 시나리오 하나다.
- **안정성 주장이 아니다.** 8런 중 3성공 — §3 의 리셋 규칙을 지켜야 한다.
