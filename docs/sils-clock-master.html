SiLS Clock Master — lockstep 시간 권위

TickGrant/TickComplete barrier로 참가자 tick을 동기 전진 · 별도 프로세스 · run당 1 · 2026-07

매 tick TickGrant를 발행하고 모든 참가자의 TickComplete를 받은 뒤에야 다음 tick을 grant한다(=barrier). 이 barrier가 실행 순서·타이밍을 고정해 동일 입력 = 동일 trace를 만든다.

1. 역할과 배선

Clock Master = TickGrant 발행자 + TickComplete 구독자. 참가자(vECU 프로브 + 입력 소스)는 그 반대. 제어 평면은 참가자와 같은 DDS 도메인(VISS_DDS_DOMAIN_ID)을 공유한다.

방향토픽타입발행 → 구독
grantsils/tick/grantTickGrantClock Master → 참가자 N
completesils/tick/completeTickComplete참가자 N → Clock Master
struct TickGrant    { string run_id; unsigned long long tick_seq; long long sim_time_ns; long long dt_ns; };
struct TickComplete { string run_id; unsigned long long tick_seq; string participant_id; long status; }; // 0=ok

2. 한 tick의 흐름 (barrier)

  • grant = broadcast, complete = barrier (순차 아님): grant는 write() 한 번으로 발행되고 DDS가 모든 참가자에게 동시 전달한다. 여러 vECU가 같은 TickGrant(seq)를 받아 병렬 실행 → 각자 participant_id로 complete. 마스터는 N개 distinct가 모여야 다음 grant → 틱 사이만 순차, 틱 안 참가자 순서는 무관(vECU 간 데이터는 tick 경계 staged = 1-tick lag).
  • 불변식: 모든 참가자의 complete를 받기 전엔 다음 tick을 grant하지 않는다 → 순서·타이밍 고정.
  • sim_time_ns = tick_seq · dt_ns — tick은 1부터, 첫 grant sim_time은 dt(0 아님). 참가자는 출력을 sim_time의 함수로 만들어 재현.
  • --tick-timeout-ms 안에 N개가 안 모이면 tick_timeout → 종료(비결정론 = 게이트 실패).

3. 실행 방법

export VISS_DDS_DOMAIN_ID=0 SILS_RUN_ID=vi SILS_CLOCK_MODE=lockstep
bin/sils_clock_master --participants 3 --ticks 40 --dt-ms 100 --tick-interval-ms 100 &   # 시간 권위
bin/vehicle_interface &        # 참가자 = vECU (SILS_CLOCK_MODE=lockstep 이면 자동 참가)
bin/sils_ego_source     --count 40 &
bin/sils_control_source --count 40 &
wait
인자기본뜻
--participants N1barrier가 기다릴 참가자 수 — lockstep 참가자 수와 정확히 일치
--ticks T10총 tick 수(다 돌면 종료)
--dt-ms D10tick당 sim_time 증가(ms)
--tick-interval-ms I0grant 사이 최소 wall 시간. 0=free-run. wall 입력 소스가 tick에 걸치게 하려면 설정
--tick-timeout-ms5000tick의 complete 수집 제한
--startup-timeout-ms10000참가자 grant 구독 초기 대기

⚠️ 대칭 규칙: --ticks == 소스 --count. 마스터가 tick을 다 돌면 grant writer 연결이 끊기고, 그걸 감지한 모든 참가자가 자동 종료(drain 후 꼬리 0). 수동 kill 불필요.

참가자 쪽 SILS_CLOCK_MODE=lockstep 이 있어야 LockstepClockSource가 선택돼 barrier에 참가한다(없으면 wall-clock으로 마스터 무시).

4. 수명과 자동 종료

5. 결정론 계약

  • sim_time_ns가 시간 권위 — 실행 속도(wall)와 무관. 참가자는 doStep/출력을 sim_time의 함수로.
  • wall 지터에 둔감 — barrier는 논리적 순서지 실시간이 아니다. Clock Master를 어디에 두든 결정론은 안 흔들린다.
  • 1-tick I/O 지연 — 단일 barrier라 sim↔vECU 결정론적 1-tick lag. zero-lag은 phased barrier(향후).

6. Trace 이벤트 & conformance

evaluate.py의 analyze_lockstep: tick_grant 존재=lockstep, tick_seq 1..N 연속, sim_time 상수 dt, barrier 닫힘, timeout 없음 → 결정론 판정.

7. 자주 겪는 함정

  • stale env — 이전 SILS_CLOCK_MODE=lockstep가 남으면 마스터 없이 vECU가 grant를 기다리며 멈춤. lockstep 안 쓸 땐 unset SILS_CLOCK_MODE SILS_RUN_ID SILS_STAGE_INPUT.
  • --participants 불일치 — 실제 참가자 수와 다르면 barrier가 안 닫혀 tick_timeout(L0).
  • --ticks ≠ --count — 어긋나면 timeout이나 꼬리. 대칭 규칙 지키면 자동 종료+꼬리0.
  • --tick-interval-ms 0 + wall 입력 — free-run이 ms 안에 질주 → wall 입력 미staging. dt에 맞춰 interval 설정.
